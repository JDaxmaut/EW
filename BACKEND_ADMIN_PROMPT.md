# BACKEND + ADMIN PROMPT — «Нескучные выходные»

> Промпт-задание для ИИ-агента (Qwen Code / Claude Code и т.п.): собрать
> **Django + Wagtail** бэкенд и **кастомную админку** с нуля.
> Партнёрский файл: `DESIGN_PROMPT.md` — палитра и визуальный язык публичной части.
> Админка делается **в той же палитре**, но по правилам инструмента: контраст,
> плотность, читаемость, никакой декоративной «дзен»-минималистичности.

## 0. ГЛАВНОЕ ПРАВИЛО ЗАДАЧИ

Админку делает **человек без технических знаний**. Это не разработчикский
интерфейс, а рабочее место менеджера, который в неделю раз 5–10 раз заходит
добавить выезд, поменять цену или заменить фото.

Отсюда обязательные требования:

1. **Никаких технических терминов в интерфейсе.** Вместо «SEO-заголовок» —
   «Заголовок для поиска», вместо «StreamField» — «Блоки страницы»,
   вместо «publish» — «Опубликовать», вместо «slug» — «адрес страницы».
   Все `verbose_name`, `help_text`, подписи кнопок — на русском, человеческим языком.
2. **Ноль догадок.** У каждого поля есть подсказка: что писать, какой длины,
   пример. У полей-изображений — прямое «Перетащите фото сюда».
3. **Показывать незакрытое.** Блок «Осталось заполнить: цена, расписание, 3 фото»
   со ссылками-якорями на конкретные поля.
4. **Безопасные значения по умолчанию.** Даты, автозаполнение заголовков из имени,
   автослаг, подстановка «Краснодарский край» по умолчанию.
5. **Ничего нельзя потерять.** Черновики, подтверждение удаления, отмена с сохранением,
   никаких необратимых действий в один клик.
6. **Три колонки** — центральный экран редактирования, слева настройки и структура,
   справа живой предпросмотр (см. §4).

```python
# trips/models.py

class Departure(models.Model):          # один выезд на конкретную дату
    destination = FK("Destination", on_delete=CASCADE, related_name="departures")
    start_date  = DateField("Дата выезда")
    end_date    = DateField("Дата возвращения", null=True, blank=True)
    price       = DecimalField("Цена за человека, ₽", max_digits=10, decimal_places=0)
    price_note  = CharField("Пометка к цене", max_length=80, blank=True)   # «при раннем бронировании −10%»
    seats_total = PositiveSmallIntegerField("Всего мест")
    seats_left  = PositiveSmallIntegerField("Свободно мест")
    meeting_point = CharField("Точка сбора", max_length=160, blank=True)
    meeting_time  = TimeField("Время сбора", null=True, blank=True)
    status      = CharField(choices=STATUSES, default="planned")           # planned / sold_out / cancelled / done
    note        = TextField("Комментарий для команды", blank=True)

    # автоподстановка свободных мест = всего мест
    # валидация: seats_left <= seats_total, end_date >= start_date, price > 0
```

### 2.2 Обязательные фичи модели

- **Slug** — `SlugField` с `editable=True`, но автозаполнение из `title`
  (`SlugField(auto_populate_from='title')`), поле подписано «Адрес страницы (латиницей)».
- **Заголовки страниц** — `page_title`, `search_description` с подсказками и
  счётчиком символов («до 160 символов»).
- **Валидация до публикации** (`PrePublishActionHook` или `clean()`):
  нельзя опубликовать без обложки, цены и хотя бы одного выезда.
  Список нарушений выводится наверху формы, а не 500-й ошибкой.
- **`search_fields`/`list_display`/`list_filter`/`ordering`** для админки:
  дата выезда, цена, свободные места, статус — чтобы менеджер фильтровал.
- **Действие «Создать выезд на 3 месяца вперёд»** — admin action, генерирует
  выезды по шаблону (день недели + время + цена + мест).
- **Массовые операции:** снять/открыть продажу, скопировать выезды на месяц.

## 3. АДМИНКА: ОБЩИЙ СТИЛЬ

### 3.1 Токены админки

```css
:root{
  /* поверхности */
  --bg:#F4FAF9;            /* фон приложения — очень светлый мятный, не чистый белый */
  --surface:#FFFFFF;
  --surface-2:#E9FBF8;     /* mint-wash: вложенные блоки, подсказки */
  --line:#C6F4EC;          /* разделители */
  --line-strong:#B4EDE2;

  /* текст — контраст обязателен */
  --text:#063D3A;          /* ink, 12.1:1 */
  --text-2:#0B5A55;        /* 80%, 8.9:1 */
  --text-3:#3E7C77;        /* 60%, 4.9:1 — только подписи ≥12px */

  /* действия */
  --primary:#00857A;       /* turquoise-700 — белый текст даёт 4.5:1 ✔ */
  --primary-hover:#007066;
  --primary-tint:#C6F4EC;
  --accent:#00C2B0;        /* рамки, иконки, hover-подчёркивания */
  --cta:#FF6B4A;           /* «Опубликовать» / главное действие */
  --cta-hover:#C93C1B;     /* белый текст 4.5:1 ✔ */
  --sun:#FFC145;           /* предупреждения, бейджи */

  /* радиусы, тени */
  --r:10px; --r-lg:14px;
  --sh:0 1px 2px rgba(6,61,58,.06), 0 4px 16px rgba(0,132,122,.06);
  --sh-pop:0 12px 40px rgba(6,61,58,.14);
}
```

**Почему так:** белый текст на `#00C2B0` даёт 2.25:1 — кнопки делаем на
`#00857A`, а `#00C2B0` используем как рамки/иконки/подсветку. Коралловый
`#FF6B4A` — только как заливка под крупный белый текст; для текста на белом —
`#C93C1B`.

### 3.2 Типографика и плотность

- Шрифт: `Inter` (подключить из `static/fonts`, без внешних CDN) + системный фолбэк.
- База 15px/1.55. Заголовки панелей 17px/600. Заголовки разделов 13px uppercase
  `tracking .12em` цветом `--text-3`.
- Лейбл поля: 13px/600 `--text-2`, обязательное поле — красная точка **после**
  лейбла, не звёздочка (звёздочка пугает и ничего не значит).
- Подсказка под полем: 12.5px `--text-3`. Подсказки **всегда видимые**, не только
  по наведению.

### 3.3 Что переопределить в стандартном Wagtail

Через хук `register("insert_global_admin_css")` отдать `css/dist/admin.css`:
`.w-admin`, `.w-panel`, `.w-field`, `.w-field__wrapper`, `.w-field__input`,
`.w-input`, `.w-label`, `.button`, `.button-longrunning`, `.w-breadcrumbs`,
`.listing`, `.w-pagination`, `.messages`, `.w-tabs`, `.object-tools`.

Ключевые переопределения:

| Элемент | Правило |
|---|---|
| Фон | `--bg` на `body.w-admin`, панели `--surface` + `--sh` + `--r-lg` |
| Панели | больше внутреннего отступа, заголовок 17px, разделитель `--line` |
| Поля | ширина ограничена, не растягиваются на весь экран — 2 колонки где можно |
| Кнопки | `--r`, uppercase-лейбл, primary = `--primary`, опасное = `--cta` |
| Ссылки | `--primary`, underline только на hover |
| Фокус | `outline 2px solid var(--accent)`, `outline-offset 2px` — везде |
| Чекбоксы/радио | кастомные, `accent-color: var(--primary)`, 18px |
| Select / date | свои иконки-календарь, без серых системных |
| InlinePanel | строки-карточки `bg: var(--surface-2)`, разделитель `--line` |
| Listing | строки 52px, hover `--primary-tint` 40%, sticky-шапка |
| Сообщения | `success` — `--primary-tint`/`--text`; `warning` — `--sun`/`#063D3A`; `error` — `#C93C1B` |
| Тёмная тема | `@media (prefers-color-scheme: dark)` — не инвертировать, а задать свои токены: `--bg:#04211F; --surface:#063D3A; --surface-2:#0B4A46; --line:#125C57; --text:#E9FBF8; --text-3:#9FD9D2` |

### 3.4 Убираем из админки лишнее
- Скрыть «Data tags», «Promote» — переименовать в «Продвижение и SEO»
  и оставить только 3–4 нужных поля (`page_title`, `search_description`,
  `og_image`, `show_in_menus`).
- Скрыть неиспользуемые блоки в редакторе StreamField (`block_counts`,
  `exclude_form_class`).
- `WAGTAILADMIN_BASE_URL` настроить, чтобы «Смотреть страницу» открывался.

### 4.2 Реализация (Wagtail 7)

- Инъекция правой колонки скриптом в edit-view (через
  `register("insert_global_admin_js")` или расширение
  `window.tarteau...` → использовать `window.wagtail` hooks
  `wagtail/admin:init` и DOM-правку `#content`).
- **Правая колонка:**
  - `<iframe>` с `page.get_preview_url()` (Wagtail preview-view),
    `transform: scale(.5)`, `transform-origin: top left`, в контейнере
    380×520 с внутренним скроллом и подписью «Предпросмотр».
  - Авто-обновление iframe после сохранения страницы (перехват ответа
    сохранения / слушать `wagtail:save`).
  - Переключатели: `Десктоп / Планшет / Телефон` (ширина iframe 1280 / 768 / 375
    со scale по ширине контейнера).
  - Кнопка «Открыть в новой вкладке».
  - **Готовность:** процент считается по полям `required` и по чек-листу
    §5.1; кольцевой прогресс `turquoise` → при 100% `sun`.
  - **«Что осталось заполнить»:** список чипов, клик — скролл к полю
    и подсветка его рамкой `--sun` на 2 секунды.
  - **Быстрые действия:** «Смотреть страницу», «Дублировать направление»,
    «Добавить выезд», «История версий».
- **Левая колонка:** своя навигация по панелям (анкоры к `w-panel`),
  под ней «Направление» (тип, цена, длительность) и «Действия» —
  дублировать / переместить в меню / архивировать.
- Адаптив:
  - `<1600px` — правая колонка сворачивается в кнопку «Предпросмотр» справа внизу
    (открывается оверлеем 420px);
  - `<1200px` — левая колонка скрыта, панели в одну колонку;
  - `<760px` — всё в одну колонку, порядок: форма → чек-лист → предпросмотр.

### 4.3 Экраны списков

- **Список направлений:** мини-превью (обложка 48×48), название, тип,
  цена, число выездов, ближайшая дата, статус. Фильтры: тип, есть ли выезды,
  статус. Поиск по названию.
- **Список выездов (сниппет):** таблица с колонками «Дата · Направление · Цена ·
  Свободно мест · Статус», массовые действия, кнопка «Создать выезды на месяц».
- **Календарь выездов:** месячная сетка, цветные точки (платно/мало мест/нет мест),
  клик — редактирование. Это то, что менеджер открывает чаще всего.

## 5. «ДЛЯ ОБЫЧНОГО ЧЕЛОВЕКА» — КОНКРЕТНЫЕ ПРАВИЛА

### 5.1 Чек-лист готовности страницы
Блок в правой колонке и (дублем) внизу формы. Пункты:

- [ ] Название и подзаголовок
- [ ] Обложка (без неё карточка в каталоге пустая)
- [ ] Галерея: минимум 3 фото в hero
- [ ] Короткое описание (лид) — минимум 80 символов
- [ ] Цена «от» и длительность
- [ ] Хотя бы один выезд в расписании
- [ ] Заполнено «что взять с собой»
- [ ] Заполнено «Заголовок для поиска»

Каждый пункт кликабелен и ведёт к нужному полю.

### 5.2 Подсказки и микрообучение
- `help_text` не «Slug», а: *«Адрес страницы латиницей. Заполнять не нужно —
  мы подставим автоматически из названия. Меняйте, только если хотите
  поменять ссылку: например `/dondukovskaya`»*.
- `help_text` цены: *«От 1 900 ₽ — минимальная цена по всем выездам.
  Напишите только цифры, можно с пробелом: 1 900»*.
- Примеры текстов прямо в подсказке: *«Например: „Дикий пляж в сосновом бору,
  12 минут пешком от дороги"»*.
- Первый запуск — короткий онбординг (3 шага, показывается один раз,
  сохраняется в localStorage): «1. Создайте направление → 2. Добавьте фото →
  3. Добавьте выезды».
- Пустые состояния не «No data», а: *«Здесь появятся фото направления.
  Добавьте хотя бы 3 — от 4 карточки уже выглядят хорошо»* + кнопка.

### 5.3 Тон интерфейса
- Обращение на «вы», без восклицательных знаков в системных сообщениях.
- Кнопки — глаголы: «Добавить выезд», «Опубликовать», «Сохранить черновик».
- Никаких «К сожалению, произошла ошибка» — вместо этого точная подсказка.

### 5.4 Права
- Группа **«Редактор»**: может редактировать контент, не видит «Настройки»,
  «Пользователи», «Инструменты», не может удалять страницы.
- Группа **«Администратор»**: всё.
- В интерфейсе у редактора скрыты кнопки «Удалить» без подтверждения —
  только через модалку с вводом названия страницы.
