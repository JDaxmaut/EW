## 1. КОНЦЕПЦИЯ: «РАСПИСАНИЕ, А НЕ ВИТРИНА»

Главная ошибка таких сайтов — делать «красивый лендинг», где посетитель
должен догадываться, когда можно поехать и сколько это стоит. Поэтому
концепция сайта: **это живое расписание, у которого есть обложка.**

Три принципа, из которых выводится вся вёрстка:

1. **Дата и цена видны на первом экране.** Не «кнопка Подробнее», а карточка
   ближайшего выезда: дата · направление · цена · свободные места · кнопка.
2. **Фотография — половина интерфейса.** Крупные фото, минимум текста,
   максимум воздуха вокруг снимка. Текст живёт на подложках, а не поверх
   случайных участков фотографии.
3. **Бирюза — среда, а не украшение.** Она в фоне секций, в линиях, в заливке
   плашек, в подсветке активных элементов. Коралл — только там, где клик.

- Бегущая строка под колонками: `mint-100` фон, текст `ink`,

### 3.2 Экран 2 — «Ближайшие выезды» (главный оффер)
- Тёмная секция `ink`, заголовок `white`, акцент курсивом `sun`.
- **Горизонтальная карусель** карточек-выездов: фото 4:5 слева, справа
  дата крупно (Cormorant 40px), направление, цена кораллом, плашка мест,
  кнопка «Записаться» (secondary, бирюза).
- Стрелки-карусели — крупные, бирюзовые, на краях секции.
- Если выездов много — счётчик «1 из 12» и точки-прогресс.

### 3.3 Экран 3 — Направления, bento-сетка
Не равная сетка, а **3 разные плитки в ряд** на десктопе:
- большая 2×2 (главное направление недели),
- две узкие 1×2 (пляж и горы),
- следующий ряд — 3 равные 1×1.
Фото во всю плитку, подпись выезжает вниз на белой карточке поверх фото
(не градиент, а плотная белая плашка с тенью — читаемость важнее красоты).
На мобильном bento превращается в одну колонку.

### 3.4 Экран 4 — «Как проходит поездка» (без иконок в кружках)
Горизонтальная лента из 4 шагов, соединённых бирюзовой линией с точками:
`6:00 сбор → 11:00 море → 18:00 обратно → 21:00 вы дома`.
Каждый шаг — время крупно + текст в 2 строки. Без картинок вообще.

### 3.5 Экран 5 — Фото-стена
Мозаика 12–16 снимков, `hover` — подпись направления в белой плашке.
Сетка intentionally «рваная»: разные соотношения сторон, одна-две плитки
шире остальных. Подпись раздела: «Мы там были. Вот как это выглядит».

### 3.6 Экран 6 — FAQ + форма записи в одной секции
Левая колонка — 4 вопроса аккордеоном, правая — короткая форма
(имя, телефон, направление выпадающим списком, комментарий).
Кнопка отправки — коралловая, во всю ширину колонки.

### 3.7 Подвал
`ink` фон, `mint-wash` текст. Три колонки: контакты и мессенджеры ·
направления списком · реквизиты. Над ними — крупная фраза
«Выходные ещё есть» и бирюзовая кнопка «Записаться».

## 6. ФОТОГРАФИИ: ГЕНЕРИРОВАТЬ ИЛИ ИСКАТЬ

Это отдельная production-задача. Фото — 60% качества сайта, поэтому
решение принимается по каждому слоту, а не «как получится».

### 6.1 Правило выбора источника

| Слот | Источник | Почему |
|---|---|---|
| Hero главной, фон, бегущая строка | **Генерация** | Нужны нестандартные кадры и пропорции, реальных фото нет |
| Иллюстрации-подложки, текстуры воды/песка | **Генерация** | Нужны абстракции, которых нет в стоках |
| Направления и выезды | **Реальные фото клиента → сток → генерация** | Приоритет: реальные снимки снимают вопрос доверия |
| Фото команды, офис | Реальные фото клиента | Генерация людей недопустима |
| Фейковые «направления» до наполнения | Плейсхолдеры (генерация Pillow) | Чтобы сайт не выглядел сломанным |

**Жёсткое правило:** фиктивные фото, сгенерированные ИИ, **никогда не выдаются
за реальные**. Если фото синтетическое — оно либо абстрактное (без людей
и без «документирующего» вида), либо подписано в интерфейсе. Подпись
«фото сгенерировано, заменить на реальные» ставится только во внутреннем
комментарии Wagtail, не на сайте.

### 6.2 Генерация — базовый промпт

Общая база для всех кадров (копить и менять только описание места):

```
{documentation}, no people, {location}, {time of day},
shot on 35mm lens, natural light, realistic photo, teal and amber grade,
saturated turquoise sea, high detail, wide 16:9, no text, no watermark,
no logo, no people, no extra limbs
```

Ключевые модификаторы:
- `no people` — обязательно для пляжей и пейзажей. Люди допускаются только
  как дальние силуэты, если вообще нужны.
- Цветокоррекция: `teal and amber grade` — это ровно то, что связывает все
  кадры в одну историю с бирюзовой палитрой сайта.
- `no text` — в кадре не должно быть табличек с текстом (особенно для
  направлений: вывески магазинов и «дикие» таблички легко превращаются
  в нечитаемый артефакт).

**Готовые промпты под ключевые слоты:**

- Hero (широкий, 16:9, 2560×1440):
```
empty wild black-sand coastline, pine forest to the horizon, turquoise sea,
early morning haze, shot on 35mm, natural light, teal and amber grade,
realistic photo, no people, no text, no watermark
```
- Карточка направления (4:3, 1200×900): `<описание места> + "documentary travel photo, no people, no text"`
- Ночная/вечерняя серия (для bento): `..., golden hour, long shadows, warm rim light, no people`
- Абстракция для фона секции: `top-down aerial view of turquoise water and sand patterns, soft gradients, no horizon, minimal`
- Текстура для тёмных секций: `dark turquoise water surface close-up, deep teal shadows, subtle ripples`

**Процесс:** сгенерировать по 4–6 кандидатов на ключевой слот → выбрать
1 → кадрировать под нужную пропорцию (сервис вроде imgproxy/параметр
`w`/`h`/`fit=crop`) → сохранить в Wagtail Images. Хранить рядом
`_prompt.txt` с исходным промптом и моделью — чтобы можно было
перегенерировать в едином стиле позже.

### 6.3 Поиск стоков (если генерация не подошла)

Допустимые источники: Unsplash, Pexels, Pixabay (проверить лицензию),
Яндекс.Фото / Фотодженика (постарше — для «наших» кадров), Flickr CC0.

Готовые запросы (RU → EN):

| Направление | EN-запрос |
|---|---|
| Ханская | `wild black sand beach cliffs sea`, `empty pebble coastline` |
| Дондуковская | `pine forest coastline dunes`, `untouched beach dunes` |
| Гиагинская | `wide shallow sandy beach turquoise water` |
| Лабинск | `river embankment town promenade summer` |
| Майкоп | `mountain plateau canyon green`, `caucasus mountains pine` |
| Белореченск | `mountain gorge green river`, `limestone cave entrance` |
| Курганинск | `quiet pebble beach calm sea` |
| Краснодар | `city embankment summer evening people` |

Правила отбора:
1. Бесплатная лицензия, без водяных знаков, без подписки — отсеивать руками,
   не брать «premium с водяным знаком».
2. Никакого хотлинка: файл скачивается и ложится в `media/images`.
3. Одна визуальная история: цветокоррекция приводится к `teal & amber`
   (редактор — любой локальный, главное результат).
4. Не брать фото, где узнаваемы конкретные люди или бренды.
5. В атрибуте страницы хранить: источник, автор, лицензия, дата скачивания.

### 6.4 Реальные фото клиента — приоритет №1
Когда придут от клиента: загрузить в Wagtail Images, применить кей для
направлений, отметить в `help_text` модели, какие слоты заполнены
(см. §6.5). Галерея направления должна состоять из реальных кадров;
сгенерированные — только в hero и в фото-стену главной, и не больше 30%.

### 6.5 Плейсхолдеры (обязательно, чтобы сайт был непустым)
Management-команда `python manage.py placeholders` генерирует через Pillow
бирюзовые плашки под каждый слот: градиент `#00C2B0 → #6FE3D6`, название
направления, пропорция, лёгкое зерно. Имя файла соответствует слоту
(`placeholder-han-skaya-1200x900.webp`). Разработчик/менеджёр видит на сайте
заглушку и понимает, что фото ещё нужно заменить. Никаких «lorem ipsum».

### 6.6 Пайплайн обработки (единый для всех источников)

| Параметр | Значение |
|---|---|
| Формат | WebP, quality 82–88 |
| Размеры | 320 / 640 / 900 / 1280 / 1920 / 2560 px по ширине |
| `srcset` | обязателен, `sizes="100vw"` для hero, `(min-width:768px) 50vw` для сетки |
| Загрузка | hero — `eager` + `fetchpriority="high"`; остальное — `lazy` |
| `loading` | всё lazy, кроме первого экрана |
| Кадрирование | `object-fit: cover`, точка фокуса задаётся редактором в Wagtail |
| Alt | обязательный, пишется редактором; для декора — `alt=""` |
| Размер файла | целевой ≤ 250 KB для карточки, ≤ 400 KB для hero |

## 7. ТЕХНИЧЕСКИЙ КАРКАС

Всё по `BACKEND_ADMIN_PROMPT.md`: Django 6 + Wagtail 7 + Tailwind 3 + Alpine.js.
Публичные шаблоны: `base.html`, главная, каталог, страница направления,
о нас, контакты, «как добраться», юр. документы, 404/500.

Из интерактива на главной: marquee (CSS), карусель выездов (Alpine + `scroll-snap`),
аккордеон FAQ (Alpine + `x-collapse`), форма (AJAX + матлогика CAPTCHA),
превью выездов на мобильном (выезд в колонку не скроллится вбок).

**Мобильный приоритет:** первая вертикаль — фото + оффер + кнопка.
Никаких горизонтальных каруселей на первом экране.

## 8. ЧЕК-ЛИСТ ПРИЁМКИ

- [ ] На первом экране видны дата, цена и свободные места — без кликов
- [ ] Ни одного блока «преимущества с иконками в кружках»
- [ ] Сетки разные: bento, карусель, лента шагов, фото-стена
- [ ] Коралл только на кнопках и ценах
- [ ] Ноль стоковых людей, улыбающихся в камеру
- [ ] Фото всех направлений — реальные либо помеченные как заглушка
- [ ] Каждое фото имеет alt и проходит через WebP-пайплайн
- [ ] Мобильный первый экран: фото + оффер + кнопка, без горизонтального скролла
- [ ] Каталог фильтруется по типу, длительности, расстоянию, дате
- [ ] Страница направления: расписание, «что взять», «что входит», галерея
- [ ] 320 / 768 / 1440 / 1920 — без переполнений
- [ ] Контраст текста ≥ 4.5:1 везде, фокус виден
- [ ] `prefers-reduced-motion` отключает marquee, карусельную анимацию и появления
